## O003｜2026-10-15｜M01 项目管理与恢复

- 基线：M00 只有治理文件，尚无可启动页面、项目 API 或数据库；本模块新增 React/TypeScript + FastAPI + SQLite 项目管理，依赖锁定，提供开发双服务与构建后单服务启动方式。
- 功能：项目列表、创建、详情、重命名；UUID 与 UTC 时间；有效名称 1–80 字，同名允许；本地保存、重复启动和刷新恢复；结构化输入/不存在/存储错误。
- 迁移修正：集成检查发现未知未来版本/校验不匹配被当作普通存储错误处理，改为拒绝应用启动。对本机权限等存储错误保留页面和 503 提示，本机日志保存诊断信息。列表同步改为按更新时间排序。
- 监督员发现：慢速旧列表响应可能覆盖刚创建/重命名的项目；开发管理进程先退出时清理遗漏子进程。阶段结论 NEEDS_CHANGES，受影响部分先修复再复审。
- 修复：写入递增读取版本，取消/忽略旧列表和详情请求，再读取最新服务端状态；启动脚本按拥有的进程组清理，即使管理进程已退出也处理后代，兼容清理时进程已消失。
- 回归：真实延迟列表响应分别覆盖创建及重命名；实际启动占用端口且忽略 SIGTERM 的子进程，覆盖管理进程存活/提前退出，确认端口释放。测试数据全部使用临时目录。
- 提交检查补充：正式 pre-commit 捕获重复清理时的间歇性 EPERM，提交被阻止，原审核失效。原因未完全确定；仅在该错误发生后通过系统 ps 核对目标进程组，确认无非僵尸成员才视为已清理；活成员、查询失败或解析不可靠时保留失败。补充空组/全僵尸/活成员/查询失败/坏输出回归，不直接吞掉权限错误。
- 验证：11 项治理回归、24 项后端行为测试、12 项真实 Chromium 浏览器测试（桌面及 390px 窄屏各 6 项）；ruff、mypy、ESLint、TypeScript、Vite 构建纳入完整门禁。浏览器覆盖创建/重命名/刷新/重开窗口、无效输入、保存失败重试、列表 503 恢复、404 和延迟旧响应。首次浏览器执行因二进制尚未安装完成而失败；安装完成后实际重跑通过，未跳过。最新独立审核及内容摘要记录在 `docs/reviews/M01.json`，未使用修复前的过时审核提交。
- 手动集成证据：构建模式的页面与 `/api/health` 均返回 200；开发模式的 5173 页面及 `/api/health` 代理也返回 200。向启动脚本发送停止信号后，重新绑定 8000 与 5173 均成功，确认本轮服务已清理。桌面和窄屏截图仅留在本机忽略目录。
