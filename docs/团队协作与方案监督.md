# 团队协作与方案监督员

| 角色 | 职责 |
| --- | --- |
| 主持/集成 | 保持单模块范围、整合结果、维护两份记录、提交推送与真实状态报告 |
| 产品 | 流程、文案确认、可用性和验收例子 |
| 语音技术 | 方言、音色与风格验证，模型适配及实测 |
| 架构/开发 | 接口、存储、队列、恢复和版本实现 |
| 质疑/质量 | 错误路径、边界、长文、退化检查 |
| 方案监督员 Plan Guardian | 独立只读核对最新决定、当前范围、代码 diff、功能证据；偏离时提醒 |

讨论聊天已建立真实 Plan Guardian 角色。代理生命周期由宿主管理；新会话不能假定旧代理仍运行，需复用或重新创建。三个必触发节点为开工、阶段完成、提交前；持续关注通过工作流触发实现，不宣称永久后台在线。监督员不与开发者同时改文件。

监督员提示词：

> 先读根目录 AGENTS.md，再完整读取 docs/协作规则.md、docs/项目方案与决策记录.md、docs/优化与问题修复记录.md 和 quality/active-module.json。仅审查当前模块。检查需求/接口/数据与错误路径，确认测试验证用户可见行为而非仅复制实现。逐条核对本轮实际错误是否记入 E 明细，区分原因确认与推断，保留失败尝试及未解决限制。尤其检查 D006 Web 先行、组件可替换、不把模拟当真实声音。输出角色署名、PASS 或 NEEDS_CHANGES、文件位置、偏离哪条决定、应如何修正、验收证据和剩余限制。最后报告你实际审查内容的 digest。发现代码变化则旧结论失效。不要修改业务代码，不生成伪造证据。

审查记录格式：

```json
{
  "module": "M00",
  "reviewer": "Plan Guardian（真实代理身份）",
  "verdict": "PASS",
  "digest": "quality_gate.py digest 的输出",
  "evidence": ["实际执行的命令与结果、真实功能判断"],
  "findings": [],
  "limitations": ["不能代替人工武汉话与音色验收"]
}
```

摘要涵盖所有入库候选文件内容和执行位，排除审查记录本身，防止自引用；Git/CI 会拒绝代码变化后的旧审查。审查记录仍是协作证明，并非密码学签名或不可绕过的权限控制，维护者不可冒用角色填 PASS。实质性结论在团队讨论聊天逐条展示，用户介入后同步给所有参与角色。

同模块补充审查使用 `docs/reviews/<模块>-<小写名称>.json`（如 `M02-docs.json`），并更新 `quality/active-module.json` 的 `review` 指向。命名必须匹配当前模块，不能跳出 `docs/reviews/`。历史审核保留当时结论，当前 PASS 必须针对最新内容摘要。阶段发言可由主代理如实转录，不能把未运行或历史通过写成当前复验。
