# 项目协作规则

## 当前有效规则（D054，2026-10-20）

用户已授权精简非必要、拖慢开发的规则。本文件是唯一现行协作规则；D018逐批强制监督、D020全员串行签署、整仓审核摘要强制门禁及D028暂停上传等旧约定不再执行。旧决策、审核与测试记录作为历史保留，不代表当前版本已验证。

## 工作方式

- 开工读本文件、相关方案/问题记录的最新部分及必要源码，不要求反复通读全部历史。明确本轮目标、风险和验收即可开展工作。
- 一个共享目录只有一个写入方；其他聊天可在独立目录工作。先核实实际文件、端口、数据与模型资源是否冲突，仅有交叉写入或共享测试风险时协调，不为互不影响的工作建立交接审批链。
- 按用户授权持续完成任务；普通实现细节不反复请示。新增费用、私人素材外传、范围外不可逆操作仍需明确授权。
- 只保留本项目main。正常提交/推送保留历史，不强推、不伪造检查通过、不用跳过Hook替代修复。

## 验证与审查

- 小改动做相关定向检查；文档改动核事实与链接，不重跑声音模型或全套浏览器。
- 数据删除、迁移、任务并发、进程回收、公开发布内容与检查基础设施等高风险改动，安排一位相关独立审查者，修复其具体发现。普通文案/展示修改不强制代理审查。
- 取消每批代码必审、四职能全员签字、无关角色“不适用”签字、总验收后再监督的串行流程。复杂跨域问题才按需增加相关角色；同一证据共享，不重复测试或代签。
- Git提交运行基础检查及索引一致性；推送核目标仓库、当前提交、干净工作区和基础检查，不再本地自动重跑全套。明确执行full或CI时才做功能验收。
- 审核摘要与路径允许清单仅保留为可选历史审计/计划资料，不因新增文件或文档变化阻断正常提交。显式使用`--review`仍严格验证对应摘要；不能把过期记录冒称当前审查。
- PostToolUse/Stop只检查未验证的内容变化，不运行功能全套；不修改宿主Hook信任。CI按改动分类：纯文档跑基础/治理检查，其余跑后端、前端及桌面/手机浏览器；隔离环境并行，保留有效断言、失败状态和证据。

## 记录与交付

- 新决定在`docs/项目方案与决策记录.md`追加一次原因、范围与取代关系；同一内容不在多份规则正文反复维护。
- 问题与修复在`docs/优化与问题修复记录.md`记录一次，保留失败尝试和实际结果。工具小错用一行汇总；数据、功能、CI或反复发生的错误写清原因、修正与验证。无错误时不强制写“无优化/无问题”占位。
- 不再要求每次文档补记重审整仓或维护独立审批JSON。审查结论直接记在相关问题/交付记录；只更新受影响证据。
- 每次交付说明已完成、实际验证、未完成/限制及提交/远端状态。没有运行、超时、失败不得写成通过；不以自动重试掩盖不稳定测试。

## 必须保留的数据与产品边界

- 私人录音、模型权重、生成音频、数据库、密钥、个人路径和原始聊天不提交。测试使用人工文本及合成素材；CI工件仅上传指定隔离测试目录，不上传整个`.quality-local`。
- 删除操作按已批准范围二次确认；保留引用保护、失败恢复、数据备份/迁移回退要求，不为绿灯删有效断言。
- 本地单人Web、固定输入快照、版本选用与拼接；当前单框输入，自动文案转换已取消。固定人物参考由后台绑定，不要求每项目上传。不支持的语速/情绪参数不得假装有效。
- 仅用免费模型；候选资源独立存放，确认不合适后仅清该候选独占资源，不动原始素材或共享环境。声音实验限定变量与样本，声音质量由试听判断，与软件验收分开。
