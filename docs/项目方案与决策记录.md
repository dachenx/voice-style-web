# 项目方案与决策总记录

记录日期：2026-10-15（Asia/Shanghai）。本文件包含初版、形成过程、变更与当前基线。历史按对话顺序回溯整理，不伪造精确时间或一致赞成；团队建议与用户决定分开标记。后续决策只追加，当前基线随已确认决定更新。

## 当前有效基线

输入普通话文案和参考人物录音，将文案改写为自然武汉话，经用户确认后，以接近参考人物的音色、语气和节奏生成音频。普通话转方言表达、方言发音、音色与韵律分别验证。

开发顺序为 **Web 先行、组件解耦、声音效果迭代验证**。声音未达标不能阻止 Web 基础流程开发；也不能对外宣称产品声音已达标。

首版采用 React + TypeScript 前端、Python + FastAPI 后台、SQLite + 本地文件、独立单任务工作进程、FFmpeg。技术栈来自团队最终开发建议，依赖版本在各模块开始时确定并锁定。M05 已实现本机 CosyVoice3 作为首个语音适配器，但最终模型不限定本机。按 D026 可比较外部开源、托管模型和商业 API；语言转换与语音合成可独立选型，以人物相似度、武汉话、自然语气、内容完整和长文稳定的实际效果优先，再综合成本、速度和维护。具体接入、费用及私人素材上传方式另行明确。

### 页面与处理流程

三个主要页面：项目列表、配音工作台、模型/组件设置。

参考音频导入/裁剪 → 普通话原稿 → 武汉话改写及对照 → 人工确认/分段/读音备注 → 短段试听 → 全文排队生成 → 版本对比/局部重生成/前后段连听 → 整篇或单段导出。

### 模块职责

| 模块 | 职责与边界 |
| --- | --- |
| 项目与本地存储 | 项目增删改查、重启恢复；元数据入 SQLite，音频落本地文件 |
| 参考音频 | 保留原文件、有效片段和预处理版本；不覆盖原始素材 |
| 文案与语言转换 | 原稿、转换草稿、人工确认稿分开；保护事实、专名、数字；转换组件可替换 |
| 术语、读音与分段 | 稳定段落编号、读音备注、按模型文本上限处理；能力不足须显示 |
| 能力注册/健康检查 | 声明语言、音频要求、长度、风格控制、上下文范围与验证状态 |
| 语音适配器 | 用统一请求连接本机或后续选定的外部模型，返回生成记录和错误；当前仅实现本机首个组件 |
| 持久任务队列 | 单任务执行、进度、失败重试、排队取消；提交时固定输入快照 |
| 试听、版本与返修 | 保留旧音频，对比/选择版本；标记过时而非覆盖，识别上下文依赖 |
| 音频整合与导出 | 按选定段落顺序拼接、停顿和必要音量处理；导出前检查未确认/失败/过时 |
| 评估与诊断 | 内容、武汉话、音色、韵律分项人工记录；记录耗时、运行环境、失败原因 |

### 可替换接口

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| 文本转换 | 原稿、源/目标语言、语体、术语 | 草稿、改写对照、不确定项 |
| 发音处理 | 确认稿、读音备注、目标模型 | 模型支持的读音提示或明确不支持 |
| 语音生成 | 确认稿、参考版本、语言、参数、上下文 | 音频、耗时、模型/参数版本、结构化错误 |
| 能力声明 | 组件标识与版本 | 支持语言、输入限制、可调参数、上下文范围、验证状态 |
| 健康检查 | 组件配置 | 连接/加载状态与失败原因 |

保存项目、参考素材、文案版本、稳定段落、任务、生成版本六类核心数据。更换全局模型/声音/风格需全文重新验证；局部修改按实际上下文范围标记过时。新语言可有自己的转换和合成链，接口预留不等于已支持。

### 范围与验收

包含本地单人配音、普通话转武汉话、人工确认、短试听、全文生成、分段返修、历史版本、下载。排除首版视频剪辑、口型同步、多人对话、多用户、批量生产、云端集群调度和未经验证的其他语言承诺。本地单人 Web 不限制模型调用位置；模型候选按 D026 开放，外部服务尚未接入。

软件检查项目恢复、任务状态/重试、快照、版本依赖、导出顺序。声音分别检查原意/数字/专名、武汉话表达与发音、音色、韵律和长段稳定性。使用测试适配器只能验证流程。参考音频长度、生成速度、模型和量化通过标准仍待真实样本及用户试听，不写死未经测试的承诺。

## 决策历史

### D001｜最早的视频多方案配音设想｜已由 D002 取代

- 来源：主聊天最初需求“自动给视频按文字给不同方案配音”。
- 初版提议：视频上传、文案、不同声音/语速方案、试听、音画对齐、字幕、批量导出。
- 形成原因：当时对象是视频配音；尚未明确参考声音复刻。
- 后续影响：仅保留文案与配音思想，视频和字幕不属于当前首版。

### D002｜改为参考音频驱动新文案配音｜有效

- 来源：用户更新为给一段音频，按这种风格（方言或其他语言）生成新文案音频。
- 讨论：音色复刻、风格模仿、方言/跨语言生成不是同一能力；参考是方言不能自动证明模型会该方言。
- 决定：先围绕音频构建；参考素材、文案、试听、生成与导出；不再承担视频处理。
- 验收：用参考人物未说过的新文案检查内容、方言、人物相似与自然度。

### D003｜真实团队讨论并公开发言｜有效

- 来源：用户要求 Agent Teams、独立讨论聊天、可看到每次发言并随时介入。
- 形成：产品、语音、架构提出观点，随后用户要求加入质疑角色。
- 决定：公开角色提交的实际观点和交叉质疑，不编造多角色对话；保留用户随时更改约束的权利。
- 边界：展示讨论发言，不显示隐藏推理，也不承诺代理永久在后台运行。

### D004｜首版武汉话，输入为普通话，预留其他语言｜有效

- 来源：用户先明确“目标是武汉话，像目标一样读出文案”，再明确提供普通话文案、留下其他语言接口。
- 产品建议：增加武汉话草稿对照和人工确认，保留数字、地址、专名。
- 语音建议：分别测改写、发音、音色和韵律；不可用音色克隆替代方言证据。
- 架构建议：文本转换、发音处理、语音生成和能力声明解耦。
- 质疑结论：语言下拉框不足以实现扩展；短段成功不能证明长段/重生成稳定。
- 决定：采用当前基线流程及通用语言字段，首版仅承诺验证范围内的武汉话。

### D005｜先验证声音再建设正式 Web｜已由 D006 取代开发前置条件

- 来源：团队第一份完整方案的风险控制建议，并在主聊天解释了样音实测方法。
- 选项：声音验证先行，或先构建通用 Web 再迭代声音组件。
- 当时理由：防止界面完成后声音效果不符合目标。
- 保留内容：真实音频对比、长文与重复生成测试、分项人工评分仍作为产品声音验收。
- 失效内容：不得再以声音测试未通过阻止基础 Web 开工。

### D006｜用户改为 Web 先行、组件可替换｜有效，优先于 D005

- 来源：用户在团队聊天提出“先建立好 Web，达不到声音目标再换模型或其他组件”。
- 决定：先构建稳定的项目/文案/任务/试听/返修流程，通过适配器替换模型及语言处理组件；软件与声音验收独立。
- 原因：可复用流程值得先建设，模型能力仍可逐步优化。
- 影响：测试适配器须明确标识；不支持的模型参数隐藏或禁用；声音验收是达标条件而非开工门槛。

### D007｜最终开发方案与六阶段划分｜作为当前实施基线

- 来源：用户要求列出模块作用，再要求开发方案；团队给出 React/TypeScript、FastAPI、SQLite、本地文件和单任务工作进程组合。
- 六阶段：项目骨架 → 文案流程 → 测试适配器生成流程 → 真实模型 → 版本返修 → 导出验收。
- 理由：先固定数据和接口，再对接耗时推理；模型依赖允许独立环境。
- 本轮细化：拆为 分模块开发与验收.md 的 M01–M08，每个模块单独验收/commit/push，避免一次性开发。此拆分不改变产品范围。

### D010｜2026-10-15｜M01 项目基础实现｜有效

- 来源：用户授权“开始 M01”；独立监督员开工审核确认范围符合 D006、D007。
- 选项与决定：沿用 React/TypeScript + Vite、FastAPI、SQLite；运行环境 Python 3.11+、Node.js 22.12+，提交精确依赖锁。仅完成项目列表、创建、详情、重命名和重启恢复。
- 项目名称去除首尾空白后为 1–80 个 Unicode 字符，不含控制字符；允许同名，内部 UUID 区分项目，创建/更新时间使用 UTC。
- 存储选择：标准库 sqlite3 配合编号 SQL 迁移与内容校验，默认仓库 data/，允许 VOICE_DATA_DIR 指定目录。相对于仅建表，迁移记录可验证重复启动、升级与未知版本；相对于立即引入 ORM，当前单表不增加额外映射层。

- 验收：前后端 lint、类型检查、构建、API 错误路径、真实服务进程重启与浏览器创建/重命名/刷新；不以页面预览代替持久化证明。
- 影响与回滚：仅 M01。保留 M00 Hook 定义；数据库有备份后方可恢复旧应用/数据库，不擅自降级 schema。本决定不取代产品方向，不扩展到 M02。

### D011｜2026-10-15｜M02 参考音频与非破坏性选段｜有效

- 来源：用户要求停止预览服务并开始下一模块；按 D007 的队列仅进入 M02。M01 已提交推送且 CI 通过，M02 从该交付提交建立独立分支，上一模块 PR 尚未合并时采用依赖该分支的 PR。
- 选项与决定：先实现原件上传、完整试听、数字起止时间选段、片段试听与当前参考选择；波形编辑、降噪、文案和模型均不在本模块。数字秒数可精确到毫秒，避免把可视波形作为上传功能的前置依赖。
- 上传范围：WAV、MP3、M4A、FLAC、OGG，单文件最多 50 MiB，解码后时长 0.1–600 秒。以上是本地导入资源限制，不代表模型的参考音频要求或最佳效果长度。
- 原始文件按字节保留；统一产生单声道 24 kHz、16-bit PCM WAV 试听副本，选段从该副本导出。每次保存生成独立片段，旧片段仍可试听和重新选用；项目只记录当前片段指针，切换不覆盖原件或旧片段。
- 处理选择：使用锁定的 imageio-ffmpeg 包提供 FFmpeg 可执行文件，避免另装平台包管理器；仅调用音频解码，不引入视频业务。使用白名单格式、有限输入字节数、解码时长及进程超时；不信任文件扩展名或 MIME 作为有效音频证明。
- 存储：SQLite 新增迁移；素材留在 data/ 的忽略目录，数据库记录 UUID、原文件名、字节数、摘要、时长和片段范围。原件落盘与数据库写入的失败须清理本次临时文件，不能出现假成功。启动时清理未提交残留，目录生命周期文件锁保证只有一个服务能执行迁移和清理，防止第二实例误删正在导入的文件。
- 验收：人工合成音频验证上传、实际解码/播放、选段范围、原件 SHA256 不变、重复保存、刷新/重启、坏文件/超限/跨项目/存储错误；浏览器覆盖桌面与窄屏。无真实人物音频入库，不作武汉话或音色效果结论。
- 影响与回滚：仅扩展 M02；迁移前停止服务并备份整个 data/，恢复须同时恢复对应数据库和素材。此决定不取代 D006 的 Web 先行方向。
