# M06 段落版本与局部返修

本模块围绕一个使用场景：全文已生成，只修改其中一段，保留满意音频并比较新候选。声音效果仍需用户试听；原 A 只是当前相对基线，本模块没有新增训练、音色调参或认可声音达标。

## 使用步骤

1. 保存并人工确认文案，选择参考及生成组件；真实组件还须核对片段准确原话。
2. 提交短段或全文任务。成功后在“段落版本与局部返修”查看每段实际音频、来源、时间、时长及输入关系。
3. 点击“选用此版本”。选用会保存，但不代表声音验收通过；新任务成功不会自动改掉原选用。
4. 编辑草稿并保存后，只受实际输入变化影响的版本标记过时。重新确认后可“按当前确认稿重生成本段”，使用当前确认、参考及组件，生成新的候选。
5. 用户已允许旧版重新选用，按钮明确为“仍选用此过时版本”；过时提示继续保留。无法核定依赖时另行提示，仍需明确选用。
6. “前后段试听”按当前服务器保存顺序播放前段选用、当前候选和后段选用；边界段只播放存在的邻段。缺少可用邻段时提示补齐，当前候选仍可单独播放。播放失败停止并提示，开始按钮可重新尝试。不生成拼接文件，也不加入停顿控制。

有未保存文案时，页面明确说明比较不包含本地修改；不能按未确认稿重生成。改稿、换参考后，旧任务及音频保留。删除段落后仍可在删除历史中播放，不能将它直接选进当前不存在的段落；重排沿用稳定段落 ID。

多窗口同时选用时只接受符合当前选用版本号和输入比较标记的请求。冲突或响应丢失不会伪装为成功，界面保留原显示并要求“刷新版本”核对服务器实际状态。输入变化、项目切换或迟到读取不能覆盖新页面。

## 各种状态的含义

| 状态 | 含义 |
| --- | --- |
| 已选用 | 用户明确保存的选择，可继续过时，不等于声音认可 |
| 匹配已保存稿 | 当前所选组件下已知实际输入相同，不保证逐字朗读正确或每次生成相同 |
| 已过时 | 有可证明的输入变化，逐项列原因；其他依赖可能仍无法核定 |
| 依赖无法核定 | 当前配置或参考等不足以作完整比较，不冒称匹配或变化 |
| 音频不可用 | 本地文件缺失、损坏或摘要不符，历史与原选用仍保留 |
| 未人工确认/组件不可调用 | 当前不能提交新任务，和旧音频是否过时分别显示 |
| 失败 | 本次任务失败，无新候选发布，不改变旧成功结果 |

## 输入关系与兼容

比较实际草稿及标点、段落 ID、参考片段 ID 与实际字节摘要、真实参考原话文本、模型/配置/关键环境身份和有效参数。只增加确认次数、原话版本号，或修改未送入当前模型的语体、术语、读音备注，不误判音频过时。模型配置沿用服务启动载入语义，更换配置后须重启；加载后的配置是否仍有效由健康检查判断。

模拟测试音仅验证软件流程，不朗读文案。真实模型同任务各段共用进程随机状态；界面保留来源任务、全文中的段序号及组件，输入匹配不保证局部重生成与原全文对应段同声，也不证明衔接自然。

仅新任务快照携带 `paragraphs-v1` 输出契约。成功结果保存真实段 WAV、段清单、依赖摘要、源快照摘要；worker 在发布前核对数量、身份、顺序、完整帧、文件摘要以及各段 PCM 顺序拼接与整篇一致。所有段与整篇在同一任务成功事务发布，任何验证/提交失败都不发布半套。

旧短段用稳定 ID 只读映射原音频，不复制、不改旧快照或数据库；旧全文没有真实边界，继续提供整篇播放和下载，不猜测切口。旧排队和失败重试保持原快照及原产物契约，请求重放不重复入队。未知输出契约明确拒绝。

## 数据与恢复

新增第 006 号迁移，只建立段落选用表；项目和段落为唯一键，保存版本 ID、并发 revision、更新时间。版本来自不可变的成功任务结果，不另建一份可漂移的段内容库。

升级前停止服务，备份整个私有数据目录和模型配置归档；升级后用当前程序读取。回退时先停止服务，恢复升级前整个目录备份及对应旧代码，不能直接用旧代码打开升级后数据库。备份应保留参考、生成结果、数据库、模型归档之间的一致性。原始音频、原话、模型、数据库与本机运行记录均不提交公开仓库。

持锁 worker 在启动时恢复中断任务，清理没有成功提交的结果目录；有测试强杀于目录 rename 后、成功事务前，确认旧成功结果和选择不变。旧任务重试只复用原输入；要使用当前稿，应点击重生成本段。
