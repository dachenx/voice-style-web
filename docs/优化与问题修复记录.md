## O004｜2026-10-15｜M02 参考音频、片段与错误恢复

- 基线：M01 仅有项目管理。按用户要求停止原预览服务，从 M01 交付提交进入 M02。本模块新增音频管理，无模型或性能改善声明。
- 功能：五种格式上传、实际解码验证、原件字节保留和下载、兼容 WAV 完整试听、毫秒起止选段、独立历史片段、当前参考切换及刷新/重启恢复。每次保存明确设为当前，试听历史不会暗中切换；上传/选段后同步项目更新时间和列表顺序。
- 上传与存储：按实际接收字节限制 50 MiB，强制白名单解码器和本地协议；解码到 600.1 秒后按实际帧数拒绝超过 600 秒的文件，不把截断当合格。45 秒超时、单音频操作上限；失败清理本次文件，事务回滚指针，启动清理未提交残留。
- 集成修正：素材及片段统一最新在前，避免刷新前后顺序变化；采用生命周期目录锁，第二实例不迁移/清理第一个实例的临时素材。重启恢复不删除已提交素材。缺失解码依赖返回可操作的错误。
- 监督员阶段结论 NEEDS_CHANGES：独立复现丢失旧片段仍可激活，覆盖有效当前指针；另自定义 FFmpeg 路径无效/不可执行时被误归为存储错误。已在激活前核对片段可读性、PCM 格式、帧数与完整数据；缺失/损坏/不可读时 503 且旧指针保持。解码进程启动 OSError 单独返回 audio_dependency_unavailable，不泄露私人路径。
- 提交前监督补充：文档曾写选段样本内容比对，而当时测试只比较帧数且输入为恒定样本，无法发现错误起点。已将核心选段用例改为随时间变化的人工 PCM，逐字节比对指定的 100–400 毫秒区间，并明确确认该区间不同于文件开头同长度内容；同时比较整段保存与完整试听副本的样本一致。
- 前端恢复：上传/保存失败保留文件或时间输入，不显示成功；刷新素材可核对连接中断前是否已完成。切换项目卸载旧请求，成功回调再次检查取消状态；延迟上传和保存响应不会写入另一项目界面。列表读取失败时阻止依赖旧状态继续提交。
- 自动验证：66 项后端测试、20 项浏览器测试和 11 项治理回归纳入完整门禁，同时运行 ruff、mypy、ESLint、TypeScript 与构建。后端真实编码/解码五种格式，原件逐字节/SHA256 比对、PCM 片段样本与时长、输入边界、归属、磁盘/事务/依赖/超时错误、并发目录锁和实际进程重启；浏览器桌面及 390px 窄屏实际播放/跳转、重复上传/选段、切换/刷新、错误重试及跨项目迟到响应。
- 测试过程：首轮 18/20 浏览器测试通过，两项被 Playwright 自身的内存文件大小上限阻止。改用临时真实超限文件后 20 项全通过，保留超限断言，未跳过。首次集成 full 的 ruff 发现从根目录与 backend/ 运行时本项目包分类不同，明确配置 backend/scripts 为 first-party 并统一导入顺序后重跑。监督员独立执行的关键后端与浏览器行为结果记录在 `docs/reviews/M02.json`，最终审核只适用于最新摘要。
- CI 修复：首次推送及 PR 的 Linux CI 在伪装 MP3 用例失败（预期 422，实际 503），因此没有宣称模块完成。取回原始日志后发现 pytest 自动把整段二进制参数放入用例名，实测三个用例 ID 超过 192 KB；[pytest 会将当前用例 ID 放入环境变量](https://docs.pytest.org/en/stable/example/simple.html#pytest-current-test-environment-variable)，而 [Linux 单个参数/环境项长度限制为 32 页](https://github.com/torvalds/linux/blob/master/include/uapi/linux/binfmts.h)。据此判断超长用例名会阻止 FFmpeg 子进程启动；改用简短稳定的测试 ID，保留所有素材、422 断言及失败清理检查，同时在失败断言中显示结构化响应便于定位。生产代码与产品决策均不改变，修复仍须独立复审并重新通过 Linux CI。

### E041｜缓存稿未加载时重新载入会静默覆盖

## 后续记录格式

优化摘要继续使用 `O编号 / 日期 / 模块 / 问题与复现 / 修改前基线 / 修改方案 / 实际测试或试听证据 / 实际改善 / 剩余限制 / 相关 D、E / 提交引用`。没有性能测量时不得填写虚构耗时或百分比提升；无优化则明确写“本模块无额外优化，仅新增功能”。

错误明细使用以下模板，追加在“后续记录格式”之前；实际修复尚未完成时先填待处理，不得预填通过：

```text
### E编号｜问题名称
- 发生日期/阶段、类型与影响：未知项明确标注。
- 现象、复现及证据来源：必要的脱敏错误摘要、文件、已有提交/CI 链接。
- 原因：已确认 / 推断 / 待定位，依据是什么。
- 尝试 1：操作、修改文件/方法、实际结果（失败也保留）。
- 尝试 2：……（同一原因追加，不同原因另建 E 编号）。
- 验证：实际命令、测试或用户确认结果；未执行明确写未执行。
- 当前状态、未解决项、关联 O/D/E：修好也保留证据缺口和限制。
```

当前提交的自引用哈希不写入自身文件，可由 Git 历史定位；在后续记录中引用已生成的提交。记录不能包含密钥、授权码、真实声音、私人路径、会话标识或原始二进制长日志。
